🛡️ Mekanisme Perlindungan OTP

Arsitektur keamanan terhadap serangan Brute-Force & Man-in-the-Middle

⚡ Anti Brute-Force Rate Limiting

Sistem membatasi maksimal 3 kali percobaan salah. Jika melampaui batas, sistem otomatis membekukan (lockdown) verifikasi selama 30 detik untuk menggagalkan bot otomatis.

Sisa Percobaan: 3 / 3 Percobaan

⏳ Single-Use & Time-Bound Token

Kode OTP dibuat dengan nilai acak kriptografis (window.crypto.getRandomValues) dan secara otomatis hangus seketika setelah digunakan (One-Time) atau setelah 60 detik kedaluwarsa.

🔒 Hubungan OTP dengan Kunci Dekripsi

Di sistem CyberShield, data sensitif yang ada di Vault membutuhkan otorisasi OTP yang valid sebelum peramban diizinkan menjalankan proses dekripsi data berharga.

Prinsip Kerahasiaan & Enkripsi End-to-End (Pasal 35)

Pengendali data wajib melindungi data pribadi dari pemrosesan tidak sah menggunakan kriptografi kuat (AES-256-GCM) sehingga pihak ketiga tidak dapat membaca data mentah.

✅

Autentikasi Bertingkat (MFA / 2FA)

Akses terhadap data sensitif dilindungi dengan otentikasi ganda menggunakan One-Time Password (OTP) dan TOTP QR Code untuk mencegah pengambilalihan akun.

✅

Hak Penghapusan Data / Right to be Forgotten (Pasal 8)

Subjek data berhak mengakhiri pemrosesan dan menghapus data pribadinya secara permanen dari sistem vault melalui tombol 'Hapus Data' kapan saja.

✅

Penyamaran Data Sensitif / PII Masking (Pasal 36)

Fitur masking otomatis menyamarkan angka sensitif pada NIK, Rekening Bank, dan Nomor Kontak saat ditampilkan pada antarmuka publik.
